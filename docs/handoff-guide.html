Chapter 1

What you're getting

Workbid is a local marketplace for home jobs. Homeowners post what needs doing; contractors send bids with a price, how long it takes, and when they can come. Accepting a bid books the date, and both sides track the job to done in the same app.

In short
  • Workbid lets homeowners post jobs and contractors bid on them.
  • One account can be both: there's a switch at the top.
  • It's free to run at first. Google charges US$25 once to publish.

How it works

For homeowners

  1. Post a job: trade, neighbourhood, details, optional budget, preferred date.
  2. Compare bids side by side: price, days of work, arrival date and window, message.
  3. Accept one. The job is booked and other bids close.
  4. Approve the contractor's work orders (line items plus GST) and log receipts.
  5. Mark the job complete.

For contractors

  1. Browse open jobs, filter by trade, search by area.
  2. Send a bid. Edit or withdraw it until the homeowner chooses.
  3. Won jobs land in the Schedule tab with date and arrival window.
  4. Tap Start work on the day, send a work order for approval.
  5. Mark it complete.

One account does both: a switch at the top of the home screen flips between Homeowner and Contractor views.

Watch out: free limits

On the free plan Firestore allows 50,000 document reads a day. The app only downloads what each person is part of: the jobs open for bids, plus their own jobs, bids, work orders and receipts. With 50 open jobs, a typical app open reads about 60–100 documents, so the free plan covers several hundred app opens a day. If you ever hit the limit, the app stops loading until midnight Pacific. Check Firestore → Usage weekly, and switch to the pay-as-you-go Blaze plan (chapter 8) before you get close.

Take ownership of the Firebase project

David created the Firebase project. He'll add you as an Owner. Then you'll remove him (or keep him as a helper with fewer permissions).

  4. Decide on David's access. When you're comfortable, change David's role to Editor or Viewer if he'll keep helping, or remove him. Only Owners can delete the project, so keep at least two Owner logins you control (for example the business account and your personal one).
Tip: billing

The project is on the free Spark plan, which needs no credit card. If you ever upgrade to the pay-as-you-go Blaze plan, it's linked to whoever adds the card. Make sure that's you, and set a budget alert at the same time (chapter 6).

Chapter 3

Set up your computer

You'll use Android Studio, Google's free tool for Android apps, to run Workbid on your phone and to make the file you upload to Google Play. Budget an hour, mostly waiting for downloads.

In short
  • Install Android Studio (free).
  • Plug in your phone and press the green ▶ button.
  • Practise with fake demo data so you don't mess up real data.

Install Android Studio

  1. Download. Go to developer.android.com/studio and download Android Studio for your computer (Windows or Mac).
  2. Install with the defaults. Click Next through the installer. When the setup wizard asks, choose Standard. It downloads the Android tools (a few GB).
  3. Open the project. Choose File → Open and pick the Workbid folder (the one containing settings.gradle.kts). Click Trust Project if asked.
  4. Wait for "Gradle sync". The bottom bar shows progress. The first time takes 5–15 minutes. When it's done there are no red error bars.

Run Workbid on your phone

  1. Turn on developer mode. On your Android phone open Settings → About phone and tap Build number seven times. You'll see "You are now a developer".
  2. Turn on USB debugging. Settings → System → Developer options → USB debugging → on.
  3. Plug in. Connect the phone with a USB cable and tap Allow on the phone's "Allow USB debugging?" prompt.
  4. Press Run. In Android Studio your phone's name appears at the top. Press the green ▶ button. Workbid installs and opens.
Watch out: this is the live app

A normal Run connects to your real Firebase database. Accounts and jobs you create are real. For practice, use the test setup below instead, or clean up afterwards (chapter 6 shows how to delete things).

Practise safely with demo data

The project includes a local stand-in for Firebase (the "emulators") filled with realistic demo jobs, bids and accounts. Nothing you do there touches real data. It's how the screenshots in this handbook were made.

One-time setup: install Node.js (the LTS version from nodejs.org). Then open a terminal in the rules-test folder (in Android Studio: View → Tool Windows → Terminal, then type cd rules-test) and run:

npm install

Each time you want to practise:

  1. Start the emulators in one terminal and leave it running:
    npm run emulators
  2. Load the demo data in a second terminal tab:
    npm run seed
  3. Run the test version of the app. Start an Android emulator in Android Studio (Device Manager → ▶ next to a virtual phone). Then in the terminal, from the main Workbid folder:
    gradlew installDebug -Pworkbid.emulator=true
    On a Mac, type ./gradlew instead of gradlew.
  4. Sign in as the demo homeowner hana@example.com or the demo contractor pat@example.com. The password for both is workbid-demo. Account → the version line says "test data (emulator)", so you always know which one you're in.
Tip

Run npm run seed again any time to reset the demo data to its starting state.

Chapter 4

Before you launch

Google reviews every app before it goes public. These are the things an app with accounts must have. Do them all before your first upload and the review is usually painless.

In short
  • Get a web address and a help@ email.
  • Publish three web pages: privacy, delete account, terms.
  • Paste those links into the app, publish the database rules, make a reviewer login.

1. Get a domain and a support email

  1. Check the name. Search Google Play and the Canadian Trademarks Database (ised-isde.canada.ca, search "trademarks database") for "Workbid". If someone already uses it for a similar service, pick a new name now. It's much cheaper than renaming later.
  2. Buy the domain from a registrar such as Namecheap, Porkbun, Cloudflare or a Canadian registrar for .ca names.
  3. Set up an email like help@yourdomain.ca. The simplest option is free email forwarding from your registrar to your business Gmail. Google Workspace (paid) is nicer if you want to send from that address.

2. Make three web pages

Google needs public links to a privacy policy and an account deletion page. A terms of use page protects you too. Templates for all three are in Appendix A. The easiest free host is Google Sites:

  1. Create the site. Go to sites.google.com while signed in to the business account → Blank site. Title it "Workbid".
  2. Add three pages (Pages panel → ＋): Privacy, Delete account, Terms. Paste each template and fill in the highlighted parts.
  3. Publish. Click Publish, choose a web address, and set it to public. Optionally connect your own domain under Settings → Custom domains.
  4. Test the links in a private browser window. They must load without signing in.

3. Put your details into the app

Open app/src/main/java/app/workbid/AppConfig.kt in Android Studio and fill in the four values between the quote marks. Anything left blank is hidden in the app.

const val SUPPORT_EMAIL = "help@yourdomain.ca"
const val PRIVACY_POLICY_URL = "https://yourdomain.ca/privacy"
const val ACCOUNT_DELETION_URL = "https://yourdomain.ca/delete-account"
const val TERMS_URL = "https://yourdomain.ca/terms"

These show up on the Account screen as Contact support, Privacy policy and Terms of use. Account deletion already works inside the app (Account → Delete account). The web page is for people who've uninstalled.

4. Publish the security rules

  1. Firebase console → Firestore Database → Rules tab.
  2. Delete everything there, paste the full contents of firestore.rules from the project folder, and click Publish.
  3. Do this again every time firestore.rules changes.
Stop: don't skip this

The app and the rules were updated together. If the old rules are still published, placing bids fails, and the protections against people changing other people's jobs aren't active.

5. Turn on password reset and verification emails

Firebase console → Authentication → Templates. Check the Password reset and Email address verification templates. Set the sender name to "Workbid" and the reply-to address to your support email. Under Settings → Authorized domains, nothing needs changing.

6. Create a reviewer account

Google's reviewers need to sign in to see the app. In the live app (or in Firebase console → Authentication → Add user), create an account such as playreview@yourdomain.ca with a strong password. Sign in once on your phone and post one sample job so the reviewer sees something. You'll give these details to Google in chapter 5.

Done when
  • Support email works (send it a test).
  • Privacy, deletion and terms pages load in a private window.
  • AppConfig.kt filled in.
  • Rules published.
  • Reviewer account signs in.

Chapter 5

Launch on Google Play

This is the full path from "no account" to "anyone can download Workbid". Do the steps in order. Where Google asks a question about the app, the right answer for Workbid is given.

In short
  • Make the upload file, and back up its key twice.
  • Fill in the store page and Google's forms (answers are given).
  • Test with 12+ people for 14 days, then go live in Canada.

Step 1 · Create your developer account

  1. Sign up. Go to play.google.com/console while signed in to the business Google account. Choose personal or organization (see chapter 2).
  2. Fill in your details. Developer name (shown on the store, e.g. "Workbid"), contact email (your support email), phone number, and a website if you have one.
  3. Pay the US$25 fee with a card.
  4. Verify your identity. Upload the government ID Google asks for (and for organizations, D-U-N-S and business details). Verification can take a few days. Google emails you when it's done.
  5. Verify your phone and email when prompted inside the Console.

Step 2 · Make the release file

Google Play takes an Android App Bundle (.aab file). It must be signed with your own upload key, a small file that proves the update came from you.

  1. Bump the version if this isn't the first upload: in app/build.gradle.kts, raise versionCode by 1 (e.g. 2 → 3) and update versionName (e.g. "1.2"). Every upload needs a higher versionCode than the last.
  2. Start the wizard. In Android Studio: Build → Generate Signed App Bundle or APK… → Android App Bundle → Next.
  3. Create the key (first time only). Click Create new… under Key store path. Save it outside the project folder, e.g. Documents/workbid-keys/workbid-upload.jks. Pick strong passwords, alias upload, validity 25+ years, and fill in your name and city.
  4. Build. Choose the release build variant → Create. When it finishes, click locate. Your file is app/release/app-release.aab.
Stop: back up the key now

Put the .jks file and both passwords in your password manager and one other safe place (an encrypted USB stick or cloud drive). Never put them in the project folder or email them. If you lose the upload key you can ask Google to reset it, but it takes time and you can't ship updates meanwhile.

Optional: build from the command line

Create a file named keystore.properties in the main Workbid folder (it's ignored by git, so it's never shared) containing:

storeFile=C:/Users/you/Documents/workbid-keys/workbid-upload.jks
storePassword=your-store-password
keyAlias=upload
keyPassword=your-key-password

Then gradlew bundleRelease builds a signed bundle into app/build/outputs/bundle/release/.

Step 3 · Create the app in Play Console

  1. Create app. Play Console → Create app. App name: Workbid. Default language: English (Canada) or English (US). App or game: App. Free or paid: Free. You can't change free to paid later.
  2. Accept the declarations (developer policies, US export laws) and click Create app.
  3. Open the Dashboard. It shows a checklist titled roughly Set up your app. The next two steps fill it in.

Because people post jobs and messages others can see, Google expects a way to report bad content, and that you act on reports. Workbid has this: the ⋮ menu on any job and the Report link on bids. Step 6 · Internal testing (you, today)

  1. Test and release → Testing → Internal testing → Create new release.
  2. If asked about Play App Signing, accept the default (Google manages the app signing key; you keep the upload key).
  3. Upload app-release.aab. Release name fills in automatically. Release notes: "First test build."
  4. Testers tab → create an email list with your own Gmail (and David's). Save, then Review release → Start rollout.
  5. Copy the join on the web link, open it on your phone, accept, and install Workbid from the Play Store. Check that sign-in, posting, bidding and the Account screen all work.

Step 7 · Closed testing (14 days, personal accounts)

If you have a personal developer account created after November 2023, Google requires a closed test with at least 12 testers who stay opted in for 14 days in a row before you can apply for production. (Organization accounts can skip to step 8, but a short closed test is still smart.)

  1. Testing → Closed testing → Create track (or use the default "Alpha") → Create new release → upload the same .aab (or a newer one).
  2. Add testers by email list or a Google Group. A Google Group (groups.google.com) is easiest: anyone you invite to the group becomes a tester.
  3. Roll out and send everyone the opt-in link from the Testers tab. Each tester must click it, tap Become a tester, then install from the Play Store.
  4. Keep them engaged. Ask testers to open the app a few times a week and try both sides. Google asks how testing went when you apply, and engaged testers make that easy.
  5. Watch the counter. The Dashboard shows how many testers have opted in and how many days remain.
Where to find 12 testers

This doubles as customer research. Invite the first contractors you recruit (chapter 7), a few homeowner friends, and family. Aim for 15–20 so dropouts don't reset your count. Ask them to post a real (small) job or bid. You'll learn more in these two weeks than any other time.

Watch out

If testers opt out and you drop below 12, the 14-day clock effectively restarts for the missing days. Remind people not to leave the test. Uninstalling isn't the same as opting out, but ask them to keep it installed.

Step 8 · Apply for production and go live

  1. When the Dashboard says you're eligible, click Apply for production and answer the questions about your testing (what testers did, what you changed, how you know it's ready). Be specific: "15 testers, 22 test jobs, fixed X and Y."

Handling a report

Anyone can report a job (⋮ menu, top right of a job) or a bid (the Report link next to Accept). They pick a reason and can add details. The person reported is never told who reported them.

Each report is saved with the reason, the job or bid, who sent it, and the status "new". Only admins can read reports: you, once you've done the one-time setup below.

One-time setup: make yourself an admin

  1. Find your user ID. Sign up in the app with your own email. Then in the Firebase console open Authentication → Users, find your email, and copy the long code in the User UID column.
  2. Create the admins list. Firestore Database → Data → + Start collection. Collection ID: admins. Click Next.
  3. Add yourself. Document ID: paste your User UID. Add one field: name note, type string, value owner. Click Save.
  4. Check it worked. Close and reopen the app, then go to Account. You'll see a new Owner tools section with Review reports.

Nobody can make themselves an admin from the app; only someone with console access can add a document to admins. To remove an admin, delete their document.

Reviewing a report in the app

  1. Open it. Account → Owner tools → Review reports. New reports are at the top, each showing the reason, the reporter's note, and the job or bid they reported.
  2. Decide. If it breaks your terms (spam, abuse, fake jobs, phone numbers or addresses in public posts), tap Remove job or Remove bid. Removing a job also removes its bids. Only open jobs can be removed this way.
  3. Or close it. If it's fine, tap Mark reviewed. Closed reports are kept under Show closed reports, and you can reopen one.
  4. Repeat offender? Disable their account in the console (next section, step 3).

The same thing in the console (for booked jobs, or if you prefer)

  1. Open reports. Firestore → Data → reports. New ones have status: "new". Each has the reason, details, the jobId and targetId (the job or bid ID), and by (who reported).
  2. Look at the content. Open jobs → the document with that jobId (or bids → the targetId).
  3. Act. For spam or abuse, delete the job or bid document. For a repeat offender, find their user ID in the postedBy or contractorId field, go to Authentication, search the user list for that ID, and disable the account.
  4. Close it. Edit the report's status field to "reviewed" (or "removed") so it leaves the app's New list.
Watch out: the console bypasses the rules

Edits you make in the console aren't checked by the security rules, so you can break things the app relies on. Safe actions: deleting an open job (also delete its bids), deleting a bid that isn't the accepted one, disabling a user. Avoid editing booked or completed jobs by hand.

Chapter 7

Getting customers

Workbid is a two-sided marketplace. Homeowners only stay if bids arrive quickly; contractors only stay if there are jobs worth bidding on. The way through is to start tiny, in one area, and do things by hand that won't scale.

In short
  • Start in a few neighbourhoods only.
  • Sign up 15–20 contractors before you tell homeowners.
  • Match the first jobs by hand: text a contractor every time a job is posted.

The five rules

  1. One area first. Pick a few neighbourhoods you can drive across in 20 minutes (for example Fairfield, James Bay and Oak Bay). A busy small area beats an empty big one. Expand only when jobs there reliably get 2+ bids within a day.
  2. Contractors before homeowners. Line up 15–20 contractors across the common trades before telling homeowners. The first homeowner who posts and hears nothing never comes back.
  3. Do it by hand. For the first 50 jobs, personally text a matching contractor every time a job is posted. That's your real product right now.
  4. Free until it works. Don't charge anyone until homeowners post repeatedly and contractors win real work. Pricing ideas are at the end of this chapter.
  5. Talk to everyone. Call your first 20 users after their first job. Ask what almost made them quit. Write it down.

Recruiting contractors

Who to target first

Small operators (1–5 people) and newly independent tradespeople. They have gaps in their calendars and no marketing budget. Big firms don't need you yet. Start with the trades homeowners need most often: handyman/general repair, plumbing, painting, electrical, carpentry, landscaping.

Where to find them

  • Your own network: anyone who's done work on your or your friends' homes.
  • Google Maps: search "plumber near Fairfield Victoria". Small businesses with 5–40 reviews are the sweet spot. Call or email from their listing.
  • Supply stores at 7am: trade counters (plumbing and electrical suppliers, lumber yards). Ask the counter staff if you can leave cards. Be brief and friendly.
  • Facebook groups and Kijiji/Craigslist "services" ads: these people are actively looking for work.
  • Trade schools and apprenticeship programs: newly certified trades looking for their own clients.

Making money later

Only once both sides are active. Common options for this kind of marketplace, from least to most friction:

  • Contractor subscription (e.g. a monthly fee for unlimited bids, with a free tier of a few bids a month). Predictable and simple.
  • Featured listings: contractors pay to appear first or show a "verified" badge after you check their licence and insurance.
  • Pay per bid or per lead. Contractors often dislike paying for leads that don't convert, so be careful.
  • Commission on booked jobs. Needs in-app payments, which is a big build and brings tax and payment regulations. Avoid this at first.

Any of these needs development work. Charging inside an Android app has Google Play billing rules, so get a developer's advice before choosing.

Chapter 8

Business basics

A short orientation for running Workbid in British Columbia. It isn't legal or tax advice. An hour with a lawyer and an accountant before you charge anyone is money well spent.

In short
  • Register a business name when you're ready (BC Registries).
  • GST only matters past $30,000 a year in revenue.
  • You connect people; you're not the contractor. Say so in your terms.

Registering the business

  • Sole proprietorship: the simplest start. In BC you can register a business name through BC Registries and Online Services (search "BC Registries name request"). The fees are modest.
  • Corporation: more paperwork and cost, but it separates your personal assets from the business. Worth considering once you charge money or hire. Ask an accountant.
  • Business bank account: keep Workbid money separate from day one. It makes taxes far easier.

GST

You must register for GST once the business's taxable revenue passes $30,000 over four consecutive calendar quarters (the "small supplier" threshold). Before that it's optional. While Workbid is free, this doesn't apply yet.

Each contractor picks the sales tax they charge when they bid: GST 5%, HST 13%, 14% or 15%, or "No sales tax" if they aren't registered. The booked job and its work orders use the rate from the accepted bid. Workbid never collects or pays the tax itself; it only shows the right totals. (BC PST usually doesn't apply to labour; Quebec's QST isn't supported yet.)

Privacy

Workbid collects names, email addresses and the content people post. In BC, private organizations are covered by BC's Personal Information Protection Act (PIPA), and the federal PIPEDA applies in many cases. In plain terms:

  • Only collect what you need, and say what you collect and why (your privacy policy does this).
  • Keep it secure. The security rules and Firebase handle most of this; keep your Google accounts locked down.
  • Let people see, correct and delete their information. The app supports deletion; handle other requests by email within 30 days.
  • Name a person responsible for privacy (you) with a contact email.
  • If there's ever a breach that could seriously harm people, you must report it. Get advice immediately.

Liability: you're the marketplace, not the contractor

  • Your terms of use should say Workbid connects homeowners and independent contractors, isn't a party to their agreements, and doesn't guarantee work quality.
  • Don't call contractors "vetted", "licensed" or "insured" unless you check, and keep records of the check.
  • Encourage written scope (work orders), and payments directly between the two parties.
  • Consider business liability insurance for Workbid itself once you're active. A broker can quote this.

Records and taxes

  • Keep receipts for business costs (the Play fee, domain, printing, software).
  • A simple bookkeeping app (Wave is free; QuickBooks and FreshBooks are paid) saves pain at tax time.
  • Report the business income on your personal return (T2125) if you're a sole proprietor.

Glossary

.aab (App Bundle)The file you upload to Google Play. Google turns it into installable apps for each phone.
.apkAn installable Android app file. Used for testing; Play wants .aab.
Android StudioGoogle's free program for building Android apps.
EmulatorA pretend phone, or pretend Firebase, running on your computer for testing.
FirebaseGoogle's service that stores Workbid's data (Firestore) and handles sign-in (Authentication).
Firestore rulesThe server-side rules that decide who can read or change each piece of data. The app can't bypass them.
Keystore / upload keyA file plus passwords that prove an upload came from you. Back it up.
versionCodeA whole number that must go up with every Play upload.
Target API levelThe Android version the app is built for. Google raises the minimum yearly.
Closed testingA Play track where only invited testers can install the app.
UGCUser-generated content: anything users post that others can see.
gitThe version history for the code. Lets you see and undo changes.
